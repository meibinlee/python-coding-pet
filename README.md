# 파이썬 타마고치

중학교 정보 수업에서 배운 코딩을 복습하며 펫을 키우는 정적 React + Vite 앱입니다. 6개 영역의 30개 템플릿에서 문제 값을 무작위 생성하고 JS 순수 함수로 정답을 계산합니다. 화면의 예시 코드는 실제 실행하지 않습니다.

서비스: https://meibinlee.github.io/python-coding-pet/

현재 규칙은 [개발 명세](DEVELOPMENT_PLAN.md), 변경·검증·배포 기록은 [진행 기록](PROGRESS.md), 작업 지침은 [AGENTS.md](AGENTS.md)를 참조하세요. [후속 개발 이력](NEXT_DEVELOPMENT_PLAN.md)은 별도 미구현 명세가 아닙니다.

## 실행

Node.js 22 또는 24에서 실행합니다.

```sh
npm ci
npm run dev
npm run test
npm run build
npm run preview
```

React + Vite + JavaScript + CSS와 localStorage만 사용합니다. DB·백엔드·인증·외부 API·친구·랭킹·분석 스크립트는 없습니다.

## 플레이와 성장

치이카와·하치와레·우사기 중 하나와 펫 이름(기본 `파이썬`)을 선택합니다. 현재 펫의 캐릭터는 시작 후 바꾸지 않으며, 기존 저장 기록에는 초기화 없이 최초 선택을 추가합니다.

- 먹이·청소·놀이 버튼으로 4지선다 문제를 풉니다. 정답은 해당 상태 +15(최대 100), XP +10. 오답은 상태 변화 없이 XP −5(최저 0)입니다.
- 한국 날짜 기준 하루 10문제. 정답·오답 모두 제출 시 1회 소비하며 답하기 전에 닫으면 소비하지 않습니다. 자정에 새로 시작하고 남은 횟수는 이월하지 않습니다.
- 같은 문제의 중복 클릭은 보상·차감·사용량에 다시 반영하지 않습니다. 다음 문제를 누를 때에만 새로 생성합니다.
- 알 → 아기: 50XP·실제 48시간·돌본 날짜 2일. 아기 → 성체: 150XP·아기 진입 후 실제 96시간·아기 단계 돌본 날짜 4일. 세 조건을 모두 충족하고 건강할 때 성장합니다.
- XP가 줄어도 도달한 단계는 유지합니다. 죽음·방치 초기화는 없습니다. 배부름·청결도·애정도의 시간 경과 감소는 생략합니다.

## 4시간마다 관리하기

알·아기 단계에서는 **먹이·청소·놀이 각각 4시간마다 미관리 XP −1**이 적용됩니다. 세 행동을 모두 놓치면 4시간에 총 −3 XP입니다. 해당 행동의 문제를 맞히면 그 행동의 관리 시간이 다시 시작됩니다.

오프라인과 낮잠 시간도 포함하며 재방문 시 한 번만 정산합니다. XP는 최저 0이고 성체부터 주기적 감소는 끝납니다. 성체의 오답 XP −5는 유지됩니다. 기존 저장에 관리 시간이 없으면 업데이트 시점부터 시작하여 과거 시간을 소급 차감하지 않습니다.

기본 돌봄·간호·쓰다듬기는 세 행동의 관리 시간을 초기화하지 않습니다. 하루 10문제 제한은 그대로이므로 세 행동을 하루 종일 4시간마다 모두 수행할 수는 없습니다. 소폭 감소한 XP는 정답 보상으로 보충할 수 있으며, 장기간 쉬려면 휴가 모드를 사용하세요.

## 돌봄과 휴식

| 기능 | 동작 |
|---|---|
| 기본 돌봄 | 한국 날짜 하루 1회. 자체 XP·상태 보상이나 문제 소비 없이 건강 관리 시각과 돌본 날짜 기록 |
| 질병·간호 | 아기부터 관리 없이 실제 24시간 초과 시 아픔. 첫 간호 후 24시간과 다른 한국 날짜의 추가 간호를 모두 충족하면 회복 |
| 쓰다듬기 | 클릭·터치·키보드로 하트·말풍선. 게임 수치·관리 시간 불변 |
| 낮잠 | 먹이 정답 후 배부름 100이면 10분 수면. 새 먹이 문제는 쉬고 청소·놀이·간호 가능. 수면 연장 없음 |
| 방 정리 | 먹이 정답 2회마다 배설물 표시, 청소 정답으로 제거. 별도 벌점 없음 |
| 휴가 | 성장·질병·회복·주기적 XP 감소 시간 정지. 제출·돌봄·간호는 쉬고 쓰다듬기 가능. 낮잠은 원래 시각에 종료 |
| 성장 앨범 | 실제 성장 시각과 모습을 중복 없이 저장. 알 수 없는 과거 시각은 만들지 않음 |

아파도 문제 풀기와 보상은 가능하지만 성장은 대기합니다. 기본 돌봄과 간호는 하루 횟수를 공유합니다. 오늘 기본 돌봄 후 새로 아프면 첫 간호 1회를 추가 허용합니다. 기본 돌봄·간호 자체는 XP를 바꾸지 않지만 실행 시점까지 지난 주기적 감소는 정산될 수 있습니다.

## 이미지와 파일 구성

사용자 제공 PNG 35장과 눈을 감은 수면 파생 PNG 7장을 `public/pets/characters/`에서 사용합니다. 세 캐릭터의 알·아기·성체에 수면 이미지가 모두 연결됩니다. 원본 참조는 `src/ref_img/`, 이미지 선택은 `src/data/characters.js`입니다. 기존 자체 제작 SVG 3개는 대체 이미지로 유지합니다. 토끼 얼굴 파비콘과 브랜드 아이콘은 `public/favicon.svg`, 푸터에는 `by.meibinlee`를 표시합니다.

- `src/data/questionTemplates.js`, `src/game/questions.js`: 정확히 30개 생성 템플릿과 보기·판정·최근 중복 완화.
- `src/game/rules.js`, `maintenance.js`: 보상·성장·방 정리 및 행동별 XP 감소.
- `src/game/storage.js`: 검증·이전·자동 저장·초기화.
- `src/game/daily.js`, `time.js`: 일일 제한·한국 날짜·여러 탭 처리.
- `src/game/health.js`, `sleep.js`, `vacation.js`, `album.js`: 건강·휴식·성장 기록.
- `src/App.jsx`, `src/components/`, `src/App.css`: 화면·상태 연결·키보드 접근 가능한 dialog.
- `tests/`: 템플릿별 100회(총 3,000회) 생성 및 육성·저장·시간 경계 테스트.

수면 파생 이미지는 내장 imagegen 도구로 생성했습니다. 공통 프롬프트: “기존 게임 스프라이트의 두 눈만 부드러운 감은 눈 곡선으로 변경. 포즈·입·귀/껍질·의상·색·질감·외곽선·배치 보존. 추가 요소와 글자 없이 투명 PNG.” 기존 성체 수면 2장은 유지했습니다.

## GitHub Pages 배포

저장소: https://github.com/meibinlee/python-coding-pet

`Test and build`는 main 푸시와 PR에서 테스트·프로젝트 경로 빌드만 수행합니다. `Deploy to GitHub Pages`는 수동 배포입니다. 배포에는 사용자 요청이 필요합니다.

1. 테스트·빌드 후 최신 커밋을 main에 push합니다.
2. 저장소 Settings → Pages에서 GitHub Actions를 사용합니다.
3. Actions → Deploy to GitHub Pages → Run workflow를 실행합니다.
4. Actions 성공과 공개 페이지의 스크립트·이미지 반영을 확인합니다.

Vite 기본 base는 `./`입니다. 명시적 프로젝트 경로는 Actions 변수 `VITE_BASE_PATH=/python-coding-pet/`, 최상위 사용자 페이지는 `/`를 사용합니다.

```sh
VITE_BASE_PATH=/python-coding-pet/ npm run build
npm run preview
# http://127.0.0.1:4173/python-coding-pet/
```

## 저장 한계와 검증

저장 키 `coding-pet-save-v1`, payload `schemaVersion: 2`를 유지합니다. 이전 저장의 이름·XP·단계·기록을 보존하고 새 관리 시간을 추가합니다. 손상된 핵심 기록은 기본값으로, 잘못된 추가 기록은 안전한 값으로 복구합니다. 저장 실패는 안내하고 현재 탭 메모리에서 진행합니다. 초기화는 확인창을 거칩니다.

현재 브라우저에만 저장되며 다른 기기와 동기화되지 않습니다. 사이트 데이터 삭제나 시크릿 모드 종료 시 기록을 잃을 수 있습니다. 실명·학번·계정은 요구하지 않습니다. 기기 시계와 저장소는 사용자가 변경할 수 있습니다.

Web Locks 지원 환경에서는 여러 탭의 갱신을 직렬 처리하며 미지원 환경에서는 최신 저장을 재확인합니다. 미지원 환경의 완전한 동시성 보장은 없습니다.

최신 테스트·빌드·배포 결과는 [진행 기록](PROGRESS.md)에 기록합니다. 2026-10-22 사용자가 기존 앱의 브라우저 동작을 확인했습니다. 이 확인은 이번 변경 전의 사용자 확인이며 새 변경의 자동 검증·브라우저 검증과 구분합니다.
