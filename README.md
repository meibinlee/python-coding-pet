# 코딩 펫 키우기

중학교 정보 수업 복습을 위한 정적 React + Vite 앱입니다. 6개 영역의 30개 템플릿에서 값을 무작위 생성하며, JavaScript 순수 함수로 정답을 계산합니다. 예시 코드를 실행하지 않습니다.

## 실행

Node.js 22 최신 LTS 또는 24 권장.

```sh
npm ci
npm run dev
npm run test
npm run build
npm run preview
```

처음에는 펫 이름(기본 코코)을 정합니다. 먹이·청소·놀기를 누르면 문제를 풀 수 있습니다. 정답은 해당 상태 +15(최대 100), XP +10이며, 오답은 XP −5(최저 0)이며 상태 수치는 그대로입니다. 같은 문제의 추가 클릭에는 차감·보상을 중복 적용하지 않습니다. 다음 문제에서만 새 문제를 생성합니다. 한국 시간 기준 하루 10문제까지 제출하며 정답·오답 모두 1문제를 사용합니다. 답하기 전에 닫으면 횟수를 쓰지 않습니다. 한국 시간 자정에 횟수가 새로 시작합니다. 50XP에 아기, 150XP에 성체로 성장합니다. 오답으로 XP가 줄어도 이미 도달한 단계는 유지하며 새로고침해도 보존합니다. 상태 감소 타이머는 생략했으며 방치로 죽거나 초기화되지 않습니다.

## 오늘의 돌봄

- 메인 화면에 오늘 제출한 문제와 남은 문제 수를 표시합니다.
- 문제를 모두 사용한 뒤에도 **기본 돌봄**과 펫 **쓰다듬기**가 가능합니다.
- 기본 돌봄은 한국 날짜 기준 하루 한 번입니다. 문제 횟수·XP·세 상태 수치는 바뀌지 않습니다.
- 체크리스트에는 정답으로 수행한 먹이·청소·놀이와 기본 돌봄을 표시합니다. 모두 완료해야 하는 의무는 없습니다.
- 펫을 클릭하거나 Tab으로 선택한 뒤 Enter/Space를 누르면 짧은 하트와 말풍선을 보여 줍니다. 게임 기록은 바뀌지 않습니다.
- 탭 복귀와 한국 자정에 오늘의 날짜를 재검사하며, 답안은 **제출 시점의 날짜**에 계산합니다.

`NEXT_DEVELOPMENT_PLAN.md` 승인본 중 일일 문제·기본 돌봄·쓰다듬기·체크리스트를 구현했습니다. **시간과 돌봄 날짜에 따른 성장, 질병·간호·회복, 낮잠은 아직 구현하지 않았습니다.** 현재 성장은 기존 XP 조건을 유지합니다. 휴가·앨범·캐릭터 교체도 후속 작업입니다.

## 파일 구성

- `src/data/questionTemplates.js`: 정확히 30개 생성 템플릿. W04는 반복 횟수를 질문합니다.
- `src/game/questions.js`: 문자열 비교(의미 있는 공백 보존), Fisher–Yates 셔플, 최근 5개 중복 재생성(최대 10회), 동일 템플릿 3연속 방지.
- `src/game/rules.js`, `storage.js`: 보상 잠금, 기존 XP 성장 및 저장 검증.
- `src/game/time.js`, `daily.js`: 한국 날짜, 일일 제출·기본 돌봄, 탭 간 저장 처리.
- `src/components/`: 펫·상태·키보드 포커스를 가두는 네이티브 문제 dialog.
- `tests/`: 템플릿당 100회 생성, 표시된 코드 리터럴에 기반한 독립 정답 계산, 보상 및 저장 테스트.

## 테스트 캐릭터 교체

직접 만든 임시 SVG인 `public/pets/egg.svg`, `baby.svg`, `adult.svg`를 원하는 이미지로 교체하세요. SVG 기준 viewBox는 `0 0 100 110`입니다. 다른 확장자를 사용하면 `src/components/Pet.jsx`와 시작 화면 이미지 경로도 수정하세요. 외부 이미지는 사용 권한을 확인하세요.

## GitHub Pages 배포

저장소: https://github.com/meibinlee/python-coding-pet

사용자 승인 후 공개 저장소로 전환하고 GitHub Actions 기반 Pages를 설정했습니다. **배포 워크플로는 수동 실행**만 허용합니다. 별도 `Test and build` 워크플로는 main 푸시와 PR에서 테스트·프로젝트 경로 빌드를 실행하며 배포하지 않습니다.

배포 주소: https://meibinlee.github.io/python-coding-pet/

1. 위 저장소에 최신 코드를 push합니다.
2. Settings → Pages → Build and deployment에서 **GitHub Actions**를 선택합니다.
3. 기본 `base`는 `./`라서 프로젝트 하위 경로의 스크립트·SVG를 상대 경로로 로드합니다. 명시적인 경로를 원하면 Settings → Secrets and variables → Actions → Variables에 `VITE_BASE_PATH`를 `/저장소이름/`으로 설정합니다. 사용자 최상위 `<username>.github.io` 저장소는 `/`입니다.
4. Actions → Deploy to GitHub Pages → Run workflow를 수동 실행합니다. `npm ci`, 테스트, 빌드를 거쳐 `dist`가 배포됩니다.
5. 배포 주소에서 이미지, 새로고침 저장 복원, 모바일 및 키보드 조작을 확인합니다.

로컬에서 프로젝트 경로 빌드 확인:

```sh
VITE_BASE_PATH=/python-coding-pet/ npm run build
npm run preview
# http://127.0.0.1:4173/python-coding-pet/ 접속
```

## 데이터 저장 한계

`coding-pet-save-v1` 키로 현재 브라우저의 localStorage에만 저장합니다. 계정·DB·백엔드·외부 API·분석 스크립트는 없습니다. 펫 이름만 입력하며 실명이나 학번을 요구하지 않습니다. 다른 브라우저나 기기와 동기화되지 않으며 사이트 데이터 삭제나 시크릿 모드 종료로 기록이 사라질 수 있습니다. 저장 실패 시 안내와 함께 메모리에서 게임을 계속합니다. 손상되거나 범위가 잘못된 핵심 기록은 기본값으로 복구합니다. 기존 v1 기록의 이름·XP·세 상태는 보존하면서 일일 기록과 마지막 관리 시각을 같은 저장 키에 확장합니다. 미래 관리 시각이나 잘못된 일일 기록은 펫을 유지하며 보정하고 안내합니다. 관리 시각은 향후 질병 기능을 위한 기록이며 현재 질병 판정에는 사용하지 않습니다. 초기화는 확인창을 통과해야 합니다.

제출과 기본 돌봄은 최신 저장 상태를 읽은 뒤 처리합니다. Web Locks 지원 브라우저에서는 같은 출처의 여러 탭을 잠금으로 직렬화합니다. 미지원 환경에서는 최신 기록을 다시 읽지만 완전한 동시 제출 방지는 보장하지 않습니다. 저장 실패 후에는 현재 탭의 메모리 기록을 우선해 횟수가 되돌아가지 않게 합니다.

클라이언트 데이터와 기기 시계는 사용자가 변경할 수 있으므로 일일 제한은 교육용 개인 플레이를 위한 장치입니다.

## 검증 기록

- Vitest 자동 테스트: 57개 통과 (템플릿별 100회, 총 3,000회 생성 포함).
- `npm run build`: 정적 프로덕션 빌드 통과.
- 테스트 도구를 Vitest 5.0.4로 업데이트하고 잠금 파일을 생성했습니다. 설치 시 npm audit 기준 취약점 0개입니다.
- 일일 10회 경계, 오답·중복 제출, 한국 자정, 기본 돌봄, 저장 실패, 여러 탭의 직렬 제출 및 기존 데이터 보존을 자동 테스트합니다.
- 이번 작업에서 실제 브라우저 검증은 Computer Use 권한이 없어 실행하지 못했습니다. 모바일·키보드·실제 Pages URL 확인은 별도로 필요합니다. 배포 여부는 GitHub Actions의 Deploy to GitHub Pages 실행 결과에서 확인할 수 있습니다.
